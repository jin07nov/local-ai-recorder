# close — フェーズを締めて記録を次へ渡す

作業ルールは [AGENTS.md](../../../AGENTS.md) に従う。
`/commit` がタスクの記録なら、`/close` は完了したフェーズの整理である。
移植・コミットの依頼だけで `/close` を続けて実行しない。

## 1. 対象フェーズと変更を確認する

`git status --porcelain=v1 --untracked-files=all`、`git log --oneline -20` と `.ai/` の4ファイルを読む。
現在フェーズの完了条件と「進行中」を確認する。将来の P1 / P2 などの未着手タスクは、現在フェーズの未完了と混同しない。

- 終わっていないタスクを勝手に完了にしない。会話・変更から判断できなければ、その項目だけ確認する。
- 退避・初期化する記録に未コミット変更がある場合は、依頼範囲内の作業を先に [commit スキル](../commit/SKILL.md) で保存する。
  無関係なユーザーの変更は取り込まず、影響するファイルを判別できない場合だけ確認する。

## 2. 消してはいけない情報を残す

- 再利用できる落とし穴を [KNOWLEDGE.md](../../../.ai/KNOWLEDGE.md) に追記する。このファイルは初期化しない。
- PLAN の後続計画、SPEC の採用方針・未確定事項、TODO の未着手 Backlog を列挙する。
- このリポジトリでは現在 `.ai/` が将来計画の正本で、README は主にオリジナル機能の説明である。
  参考元と異なり、README に必要な情報がすべて載っていると仮定して初期化しない。
- README 更新が依頼範囲に含まれる場合は、生きている情報を適切な節へ移す。
  実装済みの説明と将来計画を分け、既出の情報を重複させない。README へ移した項目を報告する。
- README 更新が対象外の場合は、PLAN / SPEC と後続 Backlog を維持し、終了したフェーズの履歴だけ整理する。
  テンプレートへの全面初期化は行わず、その理由を報告する。次の実装には着手しない。

## 3. 全面初期化する場合の手順

必要な方針・後続計画・未検証事項の退避が済み、初期化が依頼範囲に含まれる場合だけ、次のテンプレートで上書きする。
テンプレート内のパス表記はリポジトリルートを基準とする。

- [templates/PLAN.md](templates/PLAN.md)
- [templates/SPEC.md](templates/SPEC.md)
- [templates/TODO.md](templates/TODO.md)

呼び出したスキル自身の `templates/` を使い、`.agents` / `.claude` の片方に固定しない。
初期化後は次のゴールを勝手に埋めない。保持する情報と退避先を照合し、記録が消失していないか確認する。

## 4. コミットして報告する

[commit スキル](../commit/SKILL.md) に従って差分を確認・コミットする。
例: `docs: close planning phase`。初期化した TODO に今回の締め作業の完了記録を残すことは、次の計画の先取りには当たらない。

報告するものは、残した知見、移した方針・未完了タスクの場所、初期化または維持したファイル、コミットハッシュ・subject。
ブランチの変更・マージ・push・Issue や Project の更新はこのコマンドに含めない。
